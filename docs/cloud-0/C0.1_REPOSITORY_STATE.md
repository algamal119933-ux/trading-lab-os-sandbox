# C0.1 — Repository state record

Recorded in the cloud sandbox on 2026-09-06 against commit `0b44fe4` ("Initial
Trading Lab OS cloud sandbox"), the only commit in the repository's history at
the time of the audit.

## 1. What this repository is

A sanitised cloud-development copy of Trading Lab OS. It contains the
*definitions* of the stack (compose file, configs, strategy, exporter,
dashboards, scripts, docs) and none of the runtime state (no `.env`, no market
data, no trade database, no MLflow store).

## 4. Findings

### F1 — No secrets, in the tree or in history (clean)
A pattern scan of every tracked file and of every path ever added in git history
found no private key, token, exchange credential or JWT. `.env.example` ships
only `CHANGE_ME_*` placeholders. This is now enforced by
`scripts/verify_repo.py` and `tests/test_repo_hygiene.py` rather than being a
one-off observation.

### F2 — `MANIFEST.txt` was stale and listed a local-only artifact
It carried a hash for `freqtrade/user_data/config.json` — a runtime-generated,
git-ignored file — and omitted four files added later
(`baseline_benchmarks.py`, the two baseline JSON artifacts, the v1.3 patch note).
A manifest that does not match the tree is not evidence. It is now generated by
`scripts/verify_repo.py --fix` and verified in CI.

### F3 — The paper guard only checked the runtime config
`paper_guard.py` hard-coded `freqtrade/user_data/config.json`, which is never
committed. In a clean checkout — including every CI run — the guard could only
fail on "file missing", so it could not certify the config that *is* committed.
It now inspects every known paper config present and accepts explicit targets.

### F4 — The paper guard's coverage was narrower than the stated invariant
`CLAUDE.md` requires spot-only, no leverage, no futures/margin, no shorts, no
withdrawal path, bounded wallet and stake. The original guard checked
`dry_run`, `trading_mode`, `force_entry_enable`, a positive wallet, empty
key/secret, `max_open_trades` and a positive stake. Leverage, margin mode,
shorting, withdrawal keys, stake-versus-wallet, an upper wallet bound,
derivative/leveraged-token pairs and ccxt-level credentials were unchecked.

### F5 — Scripts pinned a timeframe the strategy already owns
`backtest.sh`, `lookahead.sh` and `recursive.sh` passed `--timeframe 15m` on the
command line while `PlumbingSmokeStrategy` declares `timeframe = "15m"`. Two
sources for one value is exactly the silent config/strategy mixing C0.4
forbids: change the strategy and the scripts quietly keep the old value. The
CLI flag is removed; the strategy is the single source.

### F6 — Scripts defaulted the timerange to `20250101-`
An open-ended default means two runs of "the same" backtest cover different data
as time passes. The timerange is now a required argument.

### F7 — Every script hard-coded `PlumbingSmokeStrategy`
`CLAUDE.md` is explicit that this is an infrastructure smoke strategy and must
not be rehabilitated. Hard-coding it into every research command invites exactly
that. The strategy is now a `STRATEGY` variable, still defaulting to the smoke
strategy so no existing behaviour changed silently.

### F8 — `baseline_benchmarks.py` was unrunnable outside one container
Absolute `/freqtrade/user_data/...` paths and a docstring pointing at
`C:\trading_lab_os_v1` made it untestable in CI and tied it to the owner's
machine. Paths are now arguments that default to the container layout.

### F9 — No dataset could be reproduced from this repository
Market data is intentionally excluded, and the only acquisition path was
`download-data --timeframes 15m 1h 4h --timerange 20250101-` — which matches
neither the frozen fingerprints in `CLAUDE.md` (5m and 1h, from 2025-07-01) nor
any recorded window. The frozen dataset is now described by
`research/datasets/dataset_v1.lock.json` and re-verifiable with
`scripts/audit_data.py`.

### F10 — No experiment record schema, and the MLflow logger was not one
`research/log_experiment.py` logs arbitrary keys to MLflow. It records nothing
about the config, the dataset, the strategy hash or the engine version, and
`run.example.json` contains no gate decision. C0.6 now defines the schema; the
MLflow logger remains as an optional sink.

### F11 — No CI at all, and no automated test of any invariant
The safety claims in `docs/REVIEW_REPORT_2026-09-05.md` were produced by a
manual static review. They are now executable.

### F12 — Documentation/config conflicts worth knowing
* `docs/ROADMAP.md` Gate 3 says to switch the image to `2026.7_freqai`; `.env.example` warns against it until FreqAI work starts. Not contradictory, but the roadmap is the looser statement — the `.env.example` note wins.
* `docs/ACCEPTANCE_CHECKLIST.md` describes a Docker-host procedure only; nothing described what a cloud checkout can verify. Added.
* `docs/REVIEW_REPORT_2026-09-05.md` records `MLflow v3.15.1` after a downgrade from `v3.15.2`, while `research/requirements.txt` still pins the client at `3.15.2`. These are different things (server image vs. Python client) and both are intentional; noted so the next reader does not "fix" one to match the other.

### F13 — `CLAUDE.md` names a different branch than this session was given
`CLAUDE.md` prefers `claude/cloud-0-repo-readiness`; this session is directed to
`claude/cloud-0-stage-3zbf73`. The session directive wins — pushing elsewhere is
not authorised — and the work is otherwise identical.

## 5. Configuration precedence risks (input to C0.4)

1. `config.json` is generated from the example and git-ignored, so the committed
   example is the only reviewable config. It must therefore be the thing the
   guard and CI check. (Fixed — F3.)
2. `docker-compose.yml` injects `FREQTRADE__API_SERVER__*` from `.env`. Environment
   beats the file, so the committed `OVERWRITTEN_BY_ENV` placeholders are correct
   and must not be "fixed" into real values.
3. Strategy-owned values (`minimal_roi`, `stoploss`, `timeframe`, trailing stops)
   must never appear in the config. Now enforced by the guard and a test.
4. `api_server.listen_ip_address` is `0.0.0.0` *inside* the container; host
   exposure is restricted by the `127.0.0.1:` port bindings in compose. Both
   halves are now asserted by tests, because either alone is misleading.
