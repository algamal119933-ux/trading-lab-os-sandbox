# C0.4 — Configuration isolation and precedence

## The rule

```text
CLI  >  environment (FREQTRADE__SECTION__KEY)  >  config file(s)  >  strategy
```

Freqtrade resolves settings in that order. Two practical consequences drive
everything below.

**1. The committed example is the only reviewable config.**
`freqtrade/user_data/config.json` is generated locally and git-ignored, so it can
never be reviewed, hashed or tested in CI. `config.paper.json.example` is
therefore the artifact that the paper guard, the tests and CI check. The runtime
copy is checked too, whenever it exists.

**2. A value that lives in both the config and the strategy is a silent bug.**
If `timeframe` is in the config *and* in the strategy, the config wins, the
strategy file lies, and a backtest is no longer reproducible from the strategy
alone. The paper guard now **rejects** any config containing a strategy-owned
key: `minimal_roi`, `stoploss`, `timeframe`, the trailing-stop family,
`use_custom_stoploss`, `process_only_new_candles`, `startup_candle_count`,
`order_types`, `order_time_in_force`.

For the same reason `scripts/backtest.sh` no longer passes `--timeframe`. The
strategy owns it.

## Showing the effective config without secrets

```bash
python3 scripts/effective_config.py                       # full redacted render
python3 scripts/effective_config.py --hash-only           # stable fingerprint
python3 scripts/effective_config.py --set max_open_trades=1
FREQTRADE__EXCHANGE__NAME=binance python3 scripts/effective_config.py
```

The script merges config files, then `FREQTRADE__*` environment variables, then
`--set` overrides, and redacts every credential-bearing field **before** printing
and before hashing. Two consequences worth relying on:

* the output is safe to print in CI logs and to attach as a build artifact;
* rotating a local password does **not** change `effective_config_sha256`, so a
  recorded config fingerprint stays valid across credential rotation
  (`tests/test_config_isolation.py::test_secret_value_does_not_change_the_config_hash`).

CI runs it on every push and uploads the rendered JSON as the `effective-config`
artifact.

## Where the API server binding actually is

`api_server.listen_ip_address` is `0.0.0.0` **inside the container** — required,
or the exporter on the compose network cannot reach it. Host exposure is
restricted separately by the `127.0.0.1:` prefix on every published port in
`docker-compose.yml`. Both halves are asserted
(`tests/test_paper_guard.py`, `tests/test_compose.py::test_every_published_port_is_bound_to_localhost`);
either one alone would be misleading.

## Environment variables

`docker-compose.yml` injects `FREQTRADE__API_SERVER__{USERNAME,PASSWORD,JWT_SECRET_KEY,WS_TOKEN}`
from `.env`. The `"OVERWRITTEN_BY_ENV"` strings in the committed example are
therefore correct and must not be replaced with real values. CI proves the
substitution works using dummy values only.
